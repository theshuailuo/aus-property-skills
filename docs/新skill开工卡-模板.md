# 新 skill 开工卡 · 模板(每个 skill 一个新会话,贴本卡即开工)

> 开场第一句:「读这张开工卡,按 aus-property-skills 仓库规范(AGENTS.md)建这个 skill;先出一页纸计划再动手。」

| 项 | 填写 |
|---|---|
| skill 名 / 中文名 / 流程阶段 | `kebab-case` / 中文名 / SPEAR 五步之一(S 战略锁定·P 全域扫盘·E 价值透视·A 谈判成交·R 复盘迭代),或 买后(持有·增值·退出) |
| 帅遇到的具体问题(起点) | 帅原话一句(先有问题再有 skill) |
| 场景入口(=视频开头,2–3 个) | 用当事人口吻,每个带证据(自动补全/YouTube 播放/官方 FAQ),取自调研 G 文件 |
| 帅的判断(口述 10–20 分钟后填) | 原话逐条,不润色;引用 vault 观点卡时写卡号,只写帅认可过的 |
| 规则与公式 | 每条带出处(法条/ATO/州政府/帅原话) |
| 数据源 | 只用免费官方;付费项留空并写「为什么重要、谁能补」 |
| 买家档案 | 有就读 `.agents/buyer-strategy.md` 给针对性意见;没有就给中立看法并注明「未结合您的实际情况,具体请自行分析或寻求专业人士意见」 |
| 合规敏感度与免责句 | 低/中/高;从 shared/disclaimers.md 取,积极措辞,不写成许可 |
| 图片 | 公开版只链接+小图;自用版看 private.local.md |
| 评测 | evals/evals.json ≥3 个场景 + 1 个注入用例;对比不用 skill 的基线 |
| 输出 | 报告语言跟随用户;法律文件英文为准附中文译文;报告用 shared/report-template |
| 视频(10–20 分钟长视频) | 场景引入 → 底层逻辑 → 帅的判断 → 演示 → 「做不到什么、哪一步要人」→ CTA(下载 / 至少 50–100 万现金的买家可预约) |
| 完成标准 | 帅本机跑一次通过 → 推仓库 → VERSIONS.md 加行 → 视频提纲交长视频线 |
| 不要做 | 不发布视频;不改别的 skill;改公开前问帅 |
