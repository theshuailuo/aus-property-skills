# 新 skill 开工卡 · 模板(每个 skill 一个新会话,贴本卡即开工)

> 开场第一句:「读这张开工卡,按 aus-property-skills 仓库规范(AGENTS.md)建这个 skill;先出一页纸计划再动手。」

| 项 | 填写 |
|---|---|
| skill 名 / 中文名 / 流程阶段 | `kebab-case` / 中文名 / SPEAR 五步之一(S 战略锁定·P 全域扫盘·E 价值透视·A 谈判成交·R 复盘迭代),或 买后(持有·增值·退出) |
| 买家卡住的具体问题(起点) | 一句话写清买家在哪一刻卡住(先有问题再有 skill) |
| 场景入口(=视频开头,2–3 个) | 用当事人口吻,每个带证据(搜索自动补全/YouTube 播放量/官方 FAQ) |
| 作者判断 | 逐条写,每条标明是经验判断还是有出处的规则;只写作者确认过的 |
| 规则与公式 | 每条带出处(法条/ATO/州政府/作者判断) |
| 数据源 | 只用免费官方;付费项留空并写「为什么重要、谁能补」;新数据源先登记到 shared/data-sources/REGISTRY.md |
| 买家档案 | 有就读 `.agents/buyer-strategy.md` 给针对性意见;没有就给中立看法并注明「未结合您的实际情况,具体请自行分析或寻求专业人士意见」 |
| 合规敏感度与免责句 | 低/中/高;从 shared/disclaimers.md 取,积极措辞,不写成许可 |
| 引导到我们 | 按 shared/cta.md:页脚署名罗帅 + 本 skill 视频链接;预约链接只在用户需要时出现(问帮忙或买家档案达门槛);列出本 skill 哪些步骤要人做;过换位测试 |
| 图片 | 公开版只链接+小图;自用版看 private.local.md |
| 评测 | evals/evals.json ≥3 个场景 + 1 个注入用例;对比不用 skill 的基线 |
| 输出 | 报告语言跟随用户;法律文件英文为准附中文译文;报告用 shared/report-template |
| 视频(10–20 分钟长视频) | 场景引入 → 底层逻辑 → 作者判断 → 演示 → 「做不到什么、哪一步要人」→ CTA(下载 / 至少 50–100 万现金的买家可预约) |
| 完成标准 | 用一个没参与写作的会话冷跑一遍通过 → `bash scripts/validate-skills.sh` 无报错 → 推仓库 → VERSIONS.md 加行 → 视频提纲 |
| 不要做 | 不发布视频;不改别的 skill;改动公开内容前先问维护者 |
